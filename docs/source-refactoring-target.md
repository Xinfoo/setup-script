# C 程序重构目标与目标结构

本文档定义 Arch Linux Install Script Builder 的 C 程序重构目标、模块边界和目标源码结构。这里描述的是重构完成后的架构，不代表当前仓库已经具备该目录结构。

## 重构背景

当前实现已经具备完整的方案编辑、硬件探测、JSON 持久化和 Bash 脚本生成功能，但部分源文件同时承担界面绘制、状态修改、数据计算、外部命令调用或生成流程编排。随着功能继续增加，这种职责集中会提高阅读、修改和回归验证的成本。

本次重构以现有行为为基准，重新划分模块边界，使文件位置能够直接表达其职责。重构本身不用于重新设计安装流程，也不应借机改变生成脚本的最终行为。

## 重构目标

- 让每个源文件具有清晰、有限且可以单独说明的职责。
- 将公共基础设施、环境探测、安装模型、TUI 和脚本生成明确分层。
- 把数据计算和规则判断移出 UI，使页面主要负责展示与输入分派。
- 把跨字段约束集中到 model 的验证模块，避免 UI 和 generator 各自维护一套规则。
- 将生成器拆成数据输出、流程装配、模板内容和底层写入四类职责。
- 保持 Bash 模板独立，继续保证模板中的双语注释进入最终生成脚本。
- 保持当前 JSON、软件包配置、安装方案和生成脚本的对外行为，便于逐步迁移和对比验证。
- 避免为了形式上的分层引入无实际用途的抽象、包装或运行时开销。

## 非目标

- 不在结构重构中重新设计 TUI 操作流程。
- 不改变磁盘分区、格式化、挂载、软件安装或 Secure Boot 的既有语义。
- 不为旧版 JSON 增加兼容层；版本不一致仍按既定规则明确提示是否覆盖为默认配置。
- 不把安装操作迁入 C 程序；C 程序仍然构造 Bash 脚本，实际系统修改仍由生成脚本执行。
- 不要求一次性完成全部迁移；允许按模块逐步迁移，但每一步都必须保持可构建、可测试。

## 模块边界

目标依赖方向如下：

```text
main
 ├─ ui ──────────> model
 │  ├────────────> detector
 │  └────────────> packages
 ├─ generator ───> model
 │  ├────────────> packages
 │  └────────────> common
 ├─ detector ────> common
 └─ model ───────> common

common 不依赖任何业务模块
```

边界约束：

- `common` 只提供无业务语义的底层能力，不认识安装方案、页面或脚本阶段。
- `detector` 只读取外部状态，不修改磁盘、挂载点或系统配置。
- `model` 是安装方案语义和一致性规则的唯一归属，不依赖 curses，也不直接修改系统状态。
- `ui` 展示模型、收集输入并提交修改意图，不复制存储规则或验证规则。
- `generator` 只消费通过验证的模型和软件包配置，并生成脚本；不得反向修正安装方案。
- `templates` 保存最终脚本中的静态 Bash 内容，C 文件只负责注入动态数据和确定装配顺序。
- `main.c` 只承担进程入口和顶层协调，不吸收可归入具体模块的业务逻辑。

## 目标源码结构与职责

以下内容直接对应目标目录中的每个模块。注释描述该目录或文件应承担的职责，也是后续迁移时判断代码归属的依据。

```text
src                                                             # 程序实现源码根目录；仅容纳运行代码，不放公共头文件、测试或文档。
├── common                                                      # 提供无业务语义的公共基础设施；不得依赖 model、generator 或 ui。
│   ├── atomic_file.c                                           # 封装临时文件创建、写入、同步与原子替换，避免配置或脚本只写入一半。
│   ├── process.c                                               # 统一执行外部程序、传递参数、收集输出并解释退出状态。
│   └── text.c                                                  # 提供受长度约束的字符串复制、拼接和其他通用文本操作。
├── detector                                                    # 只读探测当前运行环境，并把外部状态转换为程序可使用的快照。
│   └── storage.c                                               # 调用并解析块设备探测结果，建立磁盘、分区、文件系统及占用状态清单。
├── generator                                                   # 把已验证的安装方案和软件包配置转换为可独立执行的 Bash 安装脚本。
│   ├── emitters                                                # 把特定模型域序列化为 Bash 变量、数组或命令片段，不负责流程编排。
│   │   ├── disk.c                                              # 输出磁盘级配置，包括所选磁盘、分区策略及磁盘相关参数。
│   │   ├── package.c                                           # 输出软件包组、可选软件及安装阶段所需的软件包集合。
│   │   └── partition.c                                         # 输出分区、用途、文件系统、挂载点和挂载选项等存储明细。
│   ├── generator.c                                             # 校验生成输入、组织各生成阶段，并通过原子写入提交最终脚本。
│   ├── private.h                                               # 声明 generator 内部共享的数据、辅助函数和模块接口，不对外公开。
│   ├── shell.c                                                 # 负责 Bash 字面量转义与安全引用，保证模型数据可无歧义写入脚本。
│   ├── templates                                               # 保存按安装阶段拆分的 Bash 模板；构建时嵌入程序，运行时组合输出。
│   │   ├── chroot-base.sh                                      # 在目标系统内完成基础软件包、区域、时间、主机名和基础配置。
│   │   ├── chroot-bootloader.sh                                # 安装并配置引导加载器、启动项、内核镜像及相关回退项。
│   │   ├── chroot-desktop.sh                                   # 配置桌面环境、显示管理器、字体、输入法及桌面会话文件。
│   │   ├── chroot-optional-software.sh                         # 按用户选择安装和配置非必需软件及对应功能。
│   │   ├── chroot-preamble.sh                                  # 建立 chroot 阶段的执行环境、严格模式、变量约定和公共辅助函数。
│   │   ├── chroot-system.sh                                    # 配置用户、权限、sudo、网络、时间同步及其他系统级服务。
│   │   ├── finish-firmware.sh                                  # 完成固件相关收尾，包括 Secure Boot 文件、签名与引导资产处理。
│   │   ├── finish-main.sh                                      # 执行目标系统安装完成后的通用收尾、同步和结果提示。
│   │   ├── finish-secure-boot.sh                               # 完成 Secure Boot 专属的密钥、签名、shim 与启动项收尾。
│   │   ├── preamble.sh                                         # 生成脚本总入口的解释器声明、严格模式、常量和通用辅助函数。
│   │   ├── runtime-cleanup.sh                                  # 注册并执行退出清理，恢复临时资源、挂载和后台进程状态。
│   │   ├── runtime-filesystems.sh                              # 创建文件系统、启用交换分区、按依赖顺序挂载并生成 fstab。
│   │   ├── runtime-keep-probe.sh                               # 探测保留分区的现有文件系统和属性，为复用操作提供运行时依据。
│   │   ├── runtime-local-mirror.sh                             # 准备临时本地镜像及 nginx 进程，并管理其生命周期。
│   │   ├── runtime-logging.sh                                  # 建立安装日志、终端输出复制和错误诊断所需的日志环境。
│   │   ├── runtime-package-source.sh                           # 选择、写入并恢复 pacman 软件源和镜像配置。
│   │   ├── runtime-partitioning.sh                             # 按方案创建分区表和分区，等待内核刷新块设备视图。
│   │   ├── runtime-plan-confirmation.sh                        # 在执行破坏性步骤前展示最终方案并要求明确确认。
│   │   ├── runtime-preflight.sh                                # 检查权限、命令、网络、目标路径和关键前置条件。
│   │   ├── runtime-secure-boot-input.sh                        # 读取并验证 Secure Boot 所需密钥、证书及外部文件输入。
│   │   ├── runtime-state.sh                                    # 维护脚本执行期间的状态变量、阶段标记和共享运行时数据。
│   │   └── runtime-storage-validation.sh                       # 在真正改盘前重新核对设备身份、容量、分区与挂载冲突。
│   ├── workflow                                                # 只定义模板和动态片段的装配顺序，不承载模型规则或具体配置内容。
│   │   ├── chroot.c                                            # 组装需要在目标系统 chroot 环境中执行的各模板阶段。
│   │   ├── finish.c                                            # 组装离开 chroot 后执行的固件、Secure Boot 和最终收尾阶段。
│   │   ├── live.c                                              # 组装在 live 环境中执行的预检、分区、挂载、镜像和安装阶段。
│   │   └── preamble.c                                          # 组装脚本开头，并注入后续阶段共用的声明与辅助代码。
│   └── writer.c                                                # 提供带错误状态的顺序输出器，统一写入模板、格式化文本和动态片段。
├── main.c                                                      # 解析命令行和路径，初始化配置与模型，选择交互或非交互入口并返回最终状态。
├── model                                                       # 定义安装方案的数据结构语义、生命周期和一致性规则；不依赖 curses 或写系统状态。
│   ├── init.c                                                  # 建立安装方案的完整默认状态，并集中维护初始化与释放约定。
│   ├── json.c                                                  # 严格读写当前版本的 install-plan.json，并处理版本不一致与字段完整性。
│   ├── private.h                                               # 声明 model 内部共享的辅助函数和实现细节，不作为公共接口使用。
│   ├── storage.c                                               # 管理磁盘与分区选择、增删、身份匹配、用途、挂载点和文件系统选项。
│   ├── system.c                                                # 管理地区、身份、硬件模式、软件选择和其他非存储安装设置。
│   └── validation.c                                            # 集中检查跨字段约束并产生可供 UI 与生成器展示的明确错误。
├── packages.c                                                  # 维护内建软件包默认值，严格加载/保存 packages.json，并提供软件包组查询。
└── ui                                                          # 实现 TUI 展示和输入分派，把用户操作转换为模型意图，不重复实现业务约束。
    ├── dialogs.c                                               # 实现确认、错误、提示、选择和软件包预览等可复用模态窗口。
    ├── layout.c                                                # 计算终端区域、窗口和表格列宽位置，统一处理绘制边界与布局。
    ├── pages                                                   # 按配置主题拆分页面，负责显示当前状态并提交对应编辑意图。
    │   ├── base_system.c                                       # 编辑语言、时区、镜像、基础系统、Secure Boot和相关安装选项。
    │   ├── hardware.c                                          # 编辑Desktop或是Laptop状态，Bluetooth、显卡、固件、和硬件驱动相关选项。
    │   ├── home.c                                              # 展示安装构造器首页、主要配置入口和当前方案概览。
    │   ├── identity.c                                          # 编辑主机名、用户名、密码及用户身份相关设置。
    │   ├── output_and_execute.c                                # 选择脚本输出位置、预览生成结果，并把生成或执行请求交给上层控制器。
    │   ├── private.h                                           # 声明各页面之间共享但不向 ui 外部公开的页面辅助接口。
    │   ├── review.c                                            # 汇总并审阅最终安装方案，突出未完成项、警告和验证错误。
    │   ├── software.c                                          # 编辑桌面环境软件选择与可选软件；Enter 预览包列表，Space 切换选择。
    │   └── storage.c                                           # 实现多磁盘、分区、用途、挂载点、格式化选项和 cfdisk 交互。
    ├── private.h                                               # 声明 UI 内部状态、页面路由、绘制工具和控制器私有接口。
    └── ui.c                                                    # 管理 curses 生命周期、主事件循环、页面切换、全局快捷键、生成请求与退出流程。
```

目标结构只列出 `src/`。公共头文件仍应放在 `include/`；测试仍应放在独立测试目录，并通过公开接口验证模块行为。

## 重构完成判据

重构完成至少应满足以下条件：

- `src/` 的实际目录和文件职责与上表一致，不再保留已经被替代的旧实现文件。
- 公共头文件与 `private.h` 的可见范围明确，模块私有符号不会意外成为公共 API。
- CMake 和 VS Code 配置引用新的源文件路径，干净构建能够通过。
- 现有测试通过，并为被拆出的纯逻辑补充必要的单元测试。
- 相同 `packages.json` 和 `install-plan.json` 输入生成的安装脚本保持预期等价。
- TUI 的页面内容、快捷键、弹窗顺序和退出行为没有因文件搬迁发生意外变化。
- 非特权环境仍能运行构造器；只有明确需要权限的外部操作才在运行时拒绝执行。
- 重构后的文件中不存在为了兼容旧目录结构而长期保留的重复实现或转发层。

后续实现应以这些判据逐阶段核对。若目标职责发生变化，应先更新本文档，再调整源码。
